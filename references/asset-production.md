# 精细拆分与交付要求

## 处理方式

先列出可用的交互/装饰元素与其状态，再选择提取方法。

- 原图有完整独立轮廓：精确提取和抠图，清理外部底色、杂点与边缘污染；不能只裁出矩形。
- 存在文字覆盖、其他元素遮挡、缺失部分：用当前获准的图像编辑工具去字或补全，检查后再独立输出。不能承诺隐藏部分仍为原像素。
- 简单图标/开关：可按参考轮廓矢量化，输出平滑的白色Alpha蒙版；检查内孔和负空间，不能留下黑色实心“洞”。SVG与PNG必须一致。
- 面板/按钮：给无字底图及必要状态。尽量利用干净纹理和完整边框，九宫格中心可伸展、四角不变形。不要拉伸带字/图标的整体切片。
- 半身头像：完整头发与肩膀轮廓，外部实际透明；头像框独立。保持脸部高光、白发和浅色服装，不能用全局去白阈值删除它们。
- 角色/插画被裁出一半：明确缺失，按用户需求补全或取原始资源，不把半幅当作完整资产交付。

不要把某次示例中的固定阈值、椭圆坐标、头像身份或绝对路径作为通用算法。不得把图像编辑技能/工具的使用限制当作可以绕开的选项；遵守当前可用工具的约束。用户明确要求裁切/抠图时，按其请求选合规工具完成。

## 真透明与干净边缘

检查编码而不仅是外观：RGB图片、实心白背景、画进去的棋盘纹理都不满足透明要求。带Alpha也不证明主体外没有残留。遇到失败输出先尝试受支持的透明提取/编辑，无法满足时准确说明限制，不假称完成。

分别检查：

- 深、浅和彩色底下有没有白边、黑边、色键溢色、棋盘纹理或半透明脏边。
- 主体内的孔洞是否应该透明，玻璃/纸片是否应保留不透明或半透明内容。
- 是否破坏图标内孔、眼白、白发、衣服、装饰细线及自然阴影。
- 边缘贴画布是否属预期；需要外边距的素材不得截断。背景全铺、色块和有意出血可以不同。
- 半透明材质不要被强制变为二值蒙版。也不要把所有不透明面板内部当作残留背景。

原图尺寸是上限依据。放大输出或SVG重建不应宣传为无损恢复高清细节。说明贴图原生尺寸和合适的显示尺寸。

## 素材清单格式

在资源根目录保存JSON数组，例如：

```json
[
  {"name":"button-primary","file":"Sprites/button-primary.png","width":512,"height":128,"alpha_mode":"cutout","border":[24,24,24,24],"origin":"AI-cleaned underlay","role":"无字按钮底"},
  {"name":"screen-background","file":"Sprites/screen-background.png","alpha_mode":"opaque","border":[0,0,0,0],"role":"全屏背景"},
  {"name":"shadow","file":"Sprites/shadow.png","alpha_mode":"translucent","role":"可选阴影层"}
]
```

- `alpha_mode`：`cutout`有透明外部，`opaque`允许完全不透明，`translucent`允许整体半透明。按实际用途选择，不要为通过验证任意改分类。
- `border`顺序是Unity的Left、Bottom、Right、Top。
- `origin`明确区分提取/去字补全/矢量重建/原资源。`width/height`可省略，给出时必须与文件一致。
- 所有路径相对资源根目录。清单里的文件均应为最终素材；不混进参考截图或生成器失败文件。

调用（需要Pillow；使用所在环境可用的Python）：

```text
python <skill>/scripts/check_ui_assets.py --asset-root <资源根目录> --manifest <清单.json> --out <验收输出目录>
```

验收输出目录必须放在资源根目录之外，避免混入交付素材。输出 `qa-report.json` 和分页深浅底验收图。报告中的失败必须修复；警告逐项判断。角落有Alpha可能是合法出血，也可能是残底，不能自动放行。脚本不修改源素材，不做抠图、不证明视觉正确，也不验证Unity实际运行。可运行 `python <skill>/scripts/test_check_ui_assets.py` 验证脚本。

## 重组和Unity交付

以实际PNG/SVG渲染并重组页面，各文案单独渲染；多语言使用项目字体/本地化机制。给出逻辑尺寸与SafeArea策略，检查长标题、滚动列表、开关左右位置和禁用/选中区分。

导入建议：Sprite Single、Full Rect、禁用MipMap、Clamp，适当Filter Mode，正确alphaIsTransparency。压缩与分辨率按美术/平台选择；验收时可先用无压缩。不默认给所有图统一九宫格，也不默认对所有透明RGB归零（有些导入流程会做边缘颜色扩展）。

提供自动导入脚本时只作用于本次资源目录。没有用户要求不要替换现有UI或更改工程配置。主页面设置与游戏内设置可能有不同按钮：例如未进行游戏时不应呈现当前局“重新开始”。

交付明确覆盖哪些页面/状态，装饰图是否整体、内部是否已分层；动态功能需要哪些现有回调。未来视频使用最终拼装后的真实界面，不能拿已偏离玩法的示意动画作为成品演示。
